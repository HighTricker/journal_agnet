方案 A 七日泳道墙 推荐①

7 个并排"日泳道"，每列是当天任务按时间从早到晚排列。最直白地呈现"每周每天"，今天高亮。空间不够时整列横向滑动（手机上一屏看 1.5 列）。适合任务量中等、想一眼扫完整周的人。

数据映射：每个 chip = 一条"周任务"，含 周几 / 时间 / 内容 / 所属周目标。左侧色条=分类。勾选 chip → 写回完成状态 → 周目标进度更新。

方案 B 垂直时间轴串珠

经典"时间轴"形态：一条竖线串起所有时间节点（圆点=节点），按天分段、纵向滚动。最强调"时间节点"的视觉隐喻，信息密度高、占宽度小，适合塞进窄卡片。整周连续滚动浏览。

数据映射：同 A，只是渲染成时间线。节点圆环用分类色。纵向滚动天然支持"看不同日期"。

方案 C 横向滑动时间刻度 推荐②

最贴合你说的"时间轴可以滑动"：一条横向轨道，每天一栏，左侧是时间刻度，任务卡按时间钉在轨道上。鼠标按住直接拖动左右滑（也支持滚轮），像拖一条胶片。气质最接近"日程时间轴/甘特"。

swipe 按住空白处左右拖动，或用触控板横向滑

数据映射：同 A/B。横向轨道可无限延伸到下一周、上一周（滑动加载），未来扩展性最好。

方案 D 日期滑块 + 当日聚焦

顶部一排日期胶囊（滑块），点哪天下面就聚焦显示那一天的时间轴。强调"滑动看不同日期的安排"，单日视图最大、最聚焦，适合任务详细、想专注当天的人。代价是看不到整周全貌。

数据映射：同上。胶囊上的小圆点=那天有安排。切换日期纯前端，不额外请求。

📦 数据怎么存？（需要你拍板）

核心诉求：时间轴任务有「周几 + 时间 + 内容 + 所属周目标 + 完成状态」，且勾选要能反映到周目标。现有 weekly_tasks 表已经存周目标（含 分类 列，主键 Week）。三种方案：

方案① 新增独立表 weekly_timeline 我推荐

列：Week / 周几 / 时间 / 内容 / 关联周目标id / 完成。一个周目标可拆成多条不同天的任务（如"读完书"→周一/周四各读一次）。勾任务 → 按 关联周目标id 回写周目标完成度。

优点：职责清晰、最灵活（1 目标 ↔ 多任务）、不动现有 weekly_tasks，符合项目"列只加不改 / 新表独立"原则。代价：多一张表 + 一套联动逻辑。

方案② 直接扩展 weekly_tasks

给每条周目标加 周几 / 时间 两列，时间轴就是 weekly_tasks 的另一种视图。优点：单一数据源、零联动（任务就是目标本身）。代价：变成"1 目标=1 时间点"，无法把一个目标拆到多天多次；且不是每个周目标都想排时间。

方案③ 复用日记的 tasks_log / time_log

时间轴聚合"本周 7 天日程表"里已填的时段任务。优点：不新增任何存储，复用你每天已经在填的日程。代价：日程任务和周目标没有现成关联字段，"勾选→周目标完成"要另建映射，反而更绕。

我的建议

选 方案①（独立 weekly_timeline 表）：和你"读完《深度工作》"这种需要拆到多天执行的目标最契合，联动关系也最干净。具体"目标完成"的判定（所有子任务完成才算 / 勾任一条就算 / 手动）我们定 demo 样式后再敲。
