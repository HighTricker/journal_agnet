# 项目概述

Journal Agent 是一个本地优先的 AI 增强型个人量化日记系统。用户通过前端界面记录每日心情、睡眠、专注力等量化数据，管理任务和 30 分钟粒度的时间切片，并撰写结构化反思。系统支持日→周→月三级数据自动聚合，内置 AI 行为科学导师（多模型切换），可读取真实数据做分析并生成邮件报告。

当前阶段：前端已用 React + TypeScript 重建（`journal-frontend/`），需要搭建 FastAPI 后端提供 REST API，替代原 Streamlit 单体架构。

**核心原则：后端只是 core/ 模块的薄包装层，所有业务逻辑已在 core/ 和 agent/ 中实现，FastAPI 路由只负责参数校验、调用现有函数、返回 JSON。**

# 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端框架 | FastAPI | REST API 服务器 |
| 运行时 | Python 3.x + Uvicorn | `uvicorn main:app --reload` |
| 数据校验 | Pydantic v2 | 请求/响应模型 |
| 业务逻辑 | 现有 `core/` 模块 | 数据读写、聚合、报告（不改） |
| AI 对话 | 现有 `agent/` 模块 | LangChain Agent + Tools（不改） |
| 数据存储 | CSV 文件（本地） | Pandas 读写，UTF-8 BOM 编码（`utf-8-sig`） |
| 前端 | React 19 + TypeScript + Vite | 运行在 `localhost:5173`（或 `127.0.0.1:3000`） |

# 约束和禁忌

1. **不用数据库**：所有数据存储在 CSV 文件中，通过 Pandas 读写，不引入 SQLite/PostgreSQL 等
2. **CSV 编码**：统一使用 `utf-8-sig`（UTF-8 BOM），与现有代码保持一致
3. **不改 core/ 和 agent/**：这两个目录的代码已经稳定运行，FastAPI 层只做薄包装
4. **CORS 配置**：允许前端 `localhost:5173` 和 `127.0.0.1:3000` 访问后端 `localhost:8000`
5. **启动命令**：`uvicorn main:app --reload --host 0.0.0.0 --port 8000`
6. **Upsert 模式**：保存数据时不是追加，而是先按主键删旧行再插入新行（core/ 函数已实现）
7. **环境变量**：敏感信息（API Key、邮箱密码）全部通过 `.env` 文件配置，不硬编码
8. **错误响应格式**：统一使用 `{"detail": "错误描述"}` 格式，与 FastAPI 默认 HTTPException 一致
9. **DataFrame ↔ JSON**：所有 Pandas DataFrame 在路由层转为 `list[dict]` 返回，使用 `df.to_dict(orient="records")`

## 1. 保存日记

- **接口**：`PUT /api/diary/{date}`
- **路径参数**：`date` — 格式 `YYYY-MM-DD`（如 `2026-03-30`）
- **请求体**：

```json
{
    "summary": {
        "Mood": 4,                          // int, 1-5 心情评分
        "Sleep_Score": 3,                   // int, 1-5 睡眠质量评分
        "Sleep_Bedtime": "22:30",           // string, HH:MM 入睡时间
        "Sleep_Waketime": "08:00",          // string, HH:MM 起床时间
        "Sleep_Hours": 9.5,                 // float, 自动计算的睡眠时长（小时）
        "Focus_Count": 6,                   // int, 番茄钟数量
        "Meditation_Minutes": 20,           // int, 静坐分钟数
        "AI_Time": 3.0,                     // float, AI 使用时间（小时）
        "Masturbation_Count": 0,            // int, 打飞机次数
        "Reflect_AI_Usage": "...",          // string, AI 使用反思
        "Reflect_AI_Learning": "...",       // string, AI 学习反思
        "Reflect_Reading": "...",           // string, 读书感受
        "Reflect_Meditation": "...",        // string, 静坐感受
        "Reflect_Good_Actions": "...",      // string, 做得好的动作
        "Reflect_Bad_Actions": "...",       // string, 需改进的动作
        "Reflect_Words_To_Self": "...",     // string, 给自己的话
        "Reflect_Thoughts": "...",          // string, 想法与灵感
        "Reflect_Deep_Reflections": "...",  // string, 深度反思
        "Reflect_Sleep_Dreams": "..."       // string, 睡眠梦境记录
    },
    "tasks": [
        {
            "计划事项": "开发后端API",
            "实际完成": "完成了3个接口",
            "状态": "⚠️",                   // "✅" / "❌" / "⚠️" / ""
            "原因分析": "时间不够"
        }
    ],
    "time_slots": [
        {
            "时间段": "00:00-00:30",         // 固定格式 HH:MM-HH:MM
            "计划": "睡觉",
            "实际": "睡觉",
            "状态": "✅",                    // "✅" / "" (空字符串)
            "备注": ""
        }
        // ... 共 48 条（00:00-00:30 到 23:30-24:00）
    ]
}
```

- **返回数据**：`{"message": "2026-03-30 日记保存成功！"}`
- **业务规则**：
  1. 解析 `date` 字符串为 `datetime.date` 对象
  2. 将 summary 字典补充自动计算字段（Diary_No 编号、Weekday 星期、Date 日期）
  3. 将 tasks 列表转为 DataFrame（加上 Date 列）
  4. 将 time_slots 列表转为 DataFrame（加上 Date 列）
  5. 调用 `data_manager.save_all_data(date_obj, summary_dict, tasks_df, time_df)`
- **日记编号计算**：以 `2026-02-18 = No.1100` 为锚点，`编号 = 1100 + (date - 2026-02-18).days`
- **调用的现有函数**：`core.data_manager.save_all_data()`
- **错误处理**：`422` 日期格式错误 / `500` 保存失败
- **状态码**：`200`

## 3. 日记元数据

- **接口**：`GET /api/diary/{date}/metadata`
- **路径参数**：`date` — 格式 `YYYY-MM-DD`
- **请求体**：无
- **返回数据**：

```json
{
    "diary_no": 1140,
    "weekday": 1,
    "weekday_name": "星期一",
    "date": "2026-03-30"
}
```

- **业务规则**：
  1. 日记编号 = `1100 + (date - datetime.date(2026, 2, 18)).days`
  2. 星期几用 `date_obj.isoweekday()`（1=周一，7=周日）
- **错误处理**：`422` 日期格式不合法
- **状态码**：`200`

## 4. 日历打点

- **接口**：`GET /api/calendar/{month}`
- **路径参数**：`month` — 格式 `YYYY-MM`（如 `2026-03`）
- **请求体**：无
- **返回数据**：

```json
{
    "dates": ["2026-03-01", "2026-03-02", "2026-03-15", "2026-03-30"]
}
```

- **业务规则**：
  1. 从 `month` 解析年份，读取 `data/summary/daily_summary_{year}.csv`
  2. 筛选 Date 列中属于该月的所有日期
  3. 返回有数据的日期列表（排序后）
- **错误处理**：`422` 月份格式不合法
- **状态码**：`200`
- **特殊说明**：如果该月没有任何日记数据，返回 `{"dates": []}`（空数组），不返回 404

## 13. AI 对话（SSE 流式）

- **接口**：`POST /api/chat`
- **路径参数**：无
- **请求体**：

```json
{
    "message": "帮我分析这周的睡眠数据",
    "model": "gemini",
    "thread_id": "abc123-def456"
}
```

- `message`：用户输入的消息文本
- `model`：模型标识（`"gemini"` / `"qwen"` / `"deepseek"`）
- `thread_id`：会话 ID，用于维护多轮对话上下文。首次对话由前端生成 UUID 传入

- **返回数据**：`text/event-stream` 格式，逐块推送

```
data: {"content": "根据你这周的"}
data: {"content": "睡眠数据分析..."}
data: {"content": "平均睡眠时长 8.2 小时"}
data: [DONE]
```

出错时：
```
event: error
data: {"detail": "大模型调用失败"}
```

- **业务规则**：
  1. 调用 `agent.agent.build_agent(model_key)` 构建 Agent
  2. 使用 `thread_id` 作为 LangGraph checkpointer 的会话标识
  3. 将 Agent 的流式输出逐块包装为 SSE 事件推送给前端
  4. Agent 内部可能调用 6 个工具（read_diary / read_csv_data / save_advice_report / generate_schedule / add_task / send_email）
- **调用的现有函数**：`agent.agent.build_agent()`
- **错误处理**：通过 SSE `event: error` 事件通知前端
- **状态码**：`200`（SSE 流）

# 开发顺序建议

1. **初始化项目**：`pip install fastapi uvicorn`，创建 `main.py`，配置 CORS
2. **日记 CRUD**：GET + PUT `/api/diary/{date}` + metadata + 日历打点 — 这 4 个接口覆盖了最核心的读写流程
3. **周记 CRUD**：GET + PUT `/api/weekly/{week}` + 聚合
4. **月记 CRUD**：GET + PUT `/api/monthly/{month}` + 聚合
5. **报告接口**：POST `/api/report/send`（后台任务）
6. **模型列表**：GET `/api/chat/models`
7. **AI 对话 SSE**：POST `/api/chat` + 会话管理 — 这是技术难度最高的部分，留到最后

每完成一组接口，在 Swagger UI（`localhost:8000/docs`）上手动测试验证。
